# 잔차 LSTM 하이퍼파라미터 탐색

## 결론

정의한 3,600개 조합에서는 **Naive를 꾸준히 이기는 잔차 LSTM 설정을 확보하지 못했다**. Validation으로 선택한 설정은 Test에서 10개 seed 중 승리 0회·동률 2회·패배 8회였고, 평균 MAE는 Naive 5.07368 대비 5.11044로 약 0.72% 나빴다. RMSE와 MAPE도 개선되지 않았다.

이번 탐색은 여기서 종료한다. 선택 설정은 탐색 결과를 기록하기 위한 값이며 권장 설정이나 성능 개선으로 채택하지 않는다. 기존 학습 기본값은 유지한다. 이 결론은 아래 탐색 범위와 현재 데이터·모델 구조에 한정되며, 모든 가능한 설정의 실패를 증명하지는 않는다.

## 탐색 범위와 절차

| 항목 | 후보 |
| --- | --- |
| 입력 길이 | 5, 10, 20, 30, 60개 관측 |
| Hidden 크기 | 4, 8, 16, 24, 32, 64 |
| 학습률 | 0.00003, 0.0001, 0.0003, 0.001, 0.003 |
| Weight decay | 0, 0.001, 0.01, 0.1 |
| 배치 크기 | 32, 64, 256 |
| 학습 손실 | MAE, MSE |

1. `datasets/krw_2020_2024.csv`의 1,249개 관측을 사용한다. 기존과 같은 시간순 70/10/20 분할로 seed 42에서 전체 조합을 평가한다.
2. Validation MAE 개선률 상위 24개를 선택한다. 전체 데이터의 앞 50%, 60%, 70%를 각각 Train으로 사용하고 바로 다음 10%를 Validation으로 삼아, seed 7·17·42에서 216개 결과를 얻는다.
3. 9회 평가의 승률을 우선하고 평균 개선률을 다음 기준으로 설정 하나를 고정한다. 최대 60 epoch, 미개선 10 epoch 조기 종료, AdamW와 gradient clipping 1.0을 사용한다.
4. 고정 설정을 10개 seed로 학습하고, 동일한 Test 250개 관측(2024-01-03~2024-12-31)을 평가한다. 이번 Test 결과를 보고 설정을 다시 고르지 않았다.

3600개 설정을 탐색하고 상위 24개를 3개 시간 구간 × 3개 seed로 비교했다.
Train 구간으로만 정규화하고 Validation MAE로 체크포인트를 선택했다. epoch 0의 Naive 동일 예측도 후보에 포함했다.
선택한 설정을 고정한 후 Test에서 10개 seed를 평가했다. 0.01%를 초과하는 MAE 개선을 승리로 집계한다.
기존 reference 실험에서 Test를 이미 관찰했으므로 완전히 새로운 holdout 검증은 아니다.

모든 seed의 Test 전체 성능과 시기별 성능을 함께 판단해야 한다. 미세한 개선만으로 통계적 우위를 단정하지 않는다.

## 개선의 불확실성

날짜 순서의 상관을 고려한 10일 블록 bootstrap 5,000회에서, seed 평균 MAE 개선률의 95% 구간은 **-1.8769% ~ 0.1321%**다. 각 seed의 절대오차를 평균한 값이며 앙상블 예측 성능은 아니다. 고정된 모델의 평가 날짜 불확실성만 추정하며, 탐색에 따른 선택 편향이나 미래 분포 변화는 포함하지 않는다.
0을 포함하므로 Naive보다 통계적으로 우수하다고 판단할 근거가 부족하다.

| 지표 | Naive | 잔차 LSTM seed 평균 | 0.01% 초과 개선 seed |
| --- | --- | --- | --- |
| MAE | 5.07368000 | 5.11044136 | 0/10 |
| RMSE | 6.82930626 | 6.85897542 | 0/10 |
| MAPE | 0.37198291 | 0.37447475 | 0/10 |

여러 seed는 동일 Test 날짜를 공유하므로 독립된 10개 시장 표본을 뜻하지 않는다.

## 해석 범위

- Validation은 체크포인트와 설정 선택에 사용했으므로 Validation 승률에는 선택에 따른 낙관적 편향이 있다. 특히 epoch 0의 예측은 Naive와 같아, Validation에서 개선이 없으면 동률로 돌아갈 수 있다. 따라서 Validation에서 지지 않았다는 사실만으로 일반화 성능을 주장하지 않는다.
- Test에서 동률인 seed 67·1024는 epoch 0이 선택된 경우다. 학습된 잔차 모델의 개선으로 집계하지 않는다.
- Test를 나눈 네 구간 중 두 구간에서는 평균적으로 개선됐지만, 나머지 두 구간의 악화로 전체 성능은 낮아졌다. 시기별 수치는 사후 진단이며 구간에 맞춰 모델을 선택하지 않았다.
- 더 큰 모델이나 다른 입력 특성이 반드시 개선된다는 근거는 이번 실험에서 얻지 못했다.

## 재현 및 근거

실제 실행은 256개 조합의 초기 탐색을 Test 평가 전에 멈추고, 완료된 결과를 재사용해 전체 3,600개로 확장했다. 동일한 탐색을 처음부터 재현하려면 프로젝트 루트의 가상환경에서 새 출력 경로로 실행한다.

```bash
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python scripts/tune_residual_lstm.py \
  --output reports/residual-search-repeat --trials 3600 --epochs 60 --workers 4
```

- [실행 조건](protocol.json): 탐색 범위, 데이터·스크립트 해시, 환경, 완료 건수
- [전체 탐색](search.csv) / [반복 Validation](validation.csv): 설정 선택의 근거
- [선택 설정](selected.json) / [Test 지표](test.csv) / [날짜별 예측](predictions.csv): 최종 평가 원자료

전체 조합의 중복 없는 실행, 24×9개 반복 평가, 고정된 설정 및 날짜별 예측에서 재계산한 지표를 확인했다. Test 값을 변조해도 체크포인트 선택과 첫 Test 예측이 변하지 않는지 확인했고 코드 정적 검사도 통과했다.
